# Migrations

The M0 migration runner creates the profile-isolated schema and its `schema_migrations` checksum ledger. M3 adds `000001_m3_definition_lifecycle.up.sql` for Access, Managed Resources and Definition lifecycle. M5 appends `000002_m5_runtime_eventing.up.sql` for authoritative Runtime state, Output Candidate, Outbox/Inbox, idempotency and the frozen Ready/Retry/Lease/Outbox access-path indexes. M6 adds `000003_m6_project_fair_scheduler.up.sql` for the durable Node Task Outbox and Project Inflight access path; Scheduling Redis remains derived coordination state and has no SQL migration. M8 adds `000004_m8_managed_resource_runtime.up.sql` for runtime resource bindings and M10 adds `000005_m10_product_surface.up.sql` for the non-authoritative Run Read Model invalidation boundary (`cancel_requested_at` and project/update lookup index). M11 adds `000006_m11_recovery_observability.up.sql`: persistent Run trace roots, durable recovery-wakeup de-duplication and safe runtime audit records. The migration backfills trace roots from durable `run.created` Outbox records before making the new column non-null.

M12 appends `000007_scheduler_fifo_batching.up.sql` for the global oldest-Ready reconciliation scan and compact Queued/Running reconstruction used by the FIFO Topic Window Scheduler.

Migration files are immutable and append-only after release. Editing an applied file causes a checksum mismatch and startup tooling must fail rather than silently rewriting history.
